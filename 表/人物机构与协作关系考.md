# 人物机构与协作关系考：所属、流动、共著、治理

> **断限：2026-11-13；初校，原始网页快照待归档（snapshot pending）。** 本表配合《关键人物谱系表》《公司兴替表》，不是新增名人录。研究的问题是：**同一个人可能同时属于不同组织、项目、论文作者群与治理机构；一段关系发生改变时，哪些身份实际上改变，哪些并没有改变？**

## 一、凡例：先判关系，再写人物

《人物谱系表》中的“甲 → 乙”通常只意味着职业经历的前后顺序，并不自动证明甲机构被乙收购、员工整体转入、知识产权归属改变，或一位研究者对某个模型拥有排他贡献。

记录每条关系时至少写明：

- **两端实体**：人、法律公司、研究团队、论文、治理机构或技术资产。不得混称 Google、Google Brain、Google DeepMind、Alphabet；也不得混称 Anthropic、LTBT、Founder LLC、董事会。
- **关系种类**：任职/离任，发起/共同创办，论文共同署名，研究领导/项目参与，治理任命/投票，指导/师承，股权/控制，技术许可/收购/招聘，机构改组；必要时用“公开声明但尚未生效”。
- **生效及终止时点**：分清实际生效日、对外公告日、论文发表日、文件回顾所指的年份；“目前”必须写截至哪一天。
- **证据对象**：当事人公告能确认其公开决定；论文能确认署名和研究结果；监管文件能确认披露口径与法律安排；二手报道不能轻易替代公司交易文书。
- **未知与否定**：“未得到入职生效日期”“未确认是否控制股份”等与肯定命题一样需要保留；缺失不是让史家推断的空格。

**示例格式**：`主体甲 —[关系类型；起讫/观察时点；状态；来源]→ 主体乙`。同一个人可以有多行，并不要求把其任职或贡献压缩成一个“主所属机构”。

## 三、关系不同，历史问题也不同

### 1. 任职关系的断裂，不等于研究关系的断裂

Ilya Sutskever、Dario Amodei 与 Jan Leike 都曾在 OpenAI 工作，后来的职业去向不同。重要的不是把所有箭头归为一场“安全派分裂”，而是分别记录当事人的职务、研究合作、公开辞职与新机构成立，再检验它们是否存在可以证明的因果联系。**同一机构出身不是相同动机的证据。**[^2][^3][^4]

### 2. 公司交易与人员流动需要分开画

Character.AI 与 Google、Adept 与 Amazon 都出现了“人才转走、技术获许可、原公司继续经营”的组合。研究者所属机构改变了，技术许可使用权可能也改变了，但不能据此说原公司所有资产已移转、公司已解散，或原团队每个人均换了雇主。财务合并报表中可能采用不同会计处理；这种会计分类仍不等于公司法律实体自动被收购。[^7][^8][^9]

### 3. 创办群体、治理集团与科研共同作者不能互相替代

Anthropic 2026 年拟议上市材料直接提供了案例：七位文件界定的共同创办者、Benjamin Mann 的创办参与、拟议 Founder LLC、LTBT、董事会与 CEO 是相互交叉却各不相同的集合。公司再重要，也不能把其论文集体劳动写成管理者个人独占成果。[^11][^12][^13]

## 四、跨篇互见与编修次序

- **《关键人物谱系表》**：仍用于速览个人履历；其待审纠错在 PR #82，不在本稿复制修改，以免并行分支冲突。
- **《Ilya Sutskever 列传》《Noam Shazeer 列传》**：均在待审 PR #82，本表的“关系行”可作为校订这些人物传中任职、合作与移交段落的参照。
- **《阿莫代兄妹合传》**：待审 PR #83；对七位创办者、Benjamin Mann 和治理股份的讨论，应与这里的关系类别互见。
- **《黄仁勋本纪》《NVIDIA 本纪》**：原文在 `main`，2026-11 离职生效日的另稿校勘在 PR #84。公司 CEO 与董事会、公司继任者之间的关系不能拿来推定私人关系或未完成调查结论。
- **《志》**：可在公司治理、科研组织与技术许可专题中详细讨论机制；关系表只核对“谁、何时、哪种关系”。

**后续建表建议**：先不引入数据库或图数据库，只用 Markdown 可审核的关系行。等来源与规模稳定之后，再考虑机器可读 CSV/JSON；不能为了可视化，把猜测的“关系强度”“派系”“实际控制人”造为数值。未核实年份、未核实当事人、未证实的利益关系均不纳入正式关系行，只入审稿问题单。
